# Final Project — 주문/결제 시스템 API

## 1. 프로젝트 목표
- 앞선 Week 0~6에서 학습한 내용을 모두 활용하여
  하나의 실제 서비스에 가까운 백엔드 API를 설계·구현한다.
- 도메인 설계, 트랜잭션 처리, 예외 처리, 테스트, 조회 성능까지 고려한다.

---

## 2. 요구 기능 (Functional Requirements)

### 2-1. 회원
- 회원가입
- 로그인(JWT)
- 내 정보 조회

### 2-2. 상품
- 상품 등록
- 상품 목록 조회 (검색/정렬)
- 상품 상세 조회

### 2-3. 주문
- 장바구니 담기
- 주문 생성
- 주문 내역 조회
- 주문 취소 (재고 복구)

### 2-4. 공통
- 인증/인가 (로그인한 사용자만 주문 가능)
- 예외 처리 일원화

---

## 3. 비기능 요구사항 (Non-Functional)

- Spring Boot 3.x + Java 21
- JPA + QueryDSL + PostgreSQL
- Redis(선택) 기반 캐싱
- @Transactional을 사용한 재고/주문 트랜잭션 처리
- 통합 테스트 작성

---

## 4. 제출물

- GitHub 코드
- ERD (이미지)
- API 명세서 (Swagger, 또는 Markdown)
- 테스트 결과 (캡처 or 로그)
- 아키텍처/설계 문서 (간략히)

---

## 5. 제출 방법
1. `feature/project-final-{이름}` 브랜치 생성
2. `project-final` 폴더 안에서 프로젝트 작업
3. 기능 단위로 커밋
4. 모든 필수 요구사항 구현 후 PR 생성

PR 본문:
- 구현한 기능 목록
- ERD 이미지 첨부
- 주요 설계 의사결정 설명 (예: 도메인 분리, 트랜잭션 경계)
- 아쉬운 점 / 리팩터링 아이디어

---

## 6. 자기 점검 체크리스트
- [ ] 요구된 기능(회원, 상품, 주문)을 모두 구현했다.
- [ ] 엔티티/도메인 구조가 과도하게 뒤엉켜 있지 않다.
- [ ] 트랜잭션이 필요한 로직에 @Transactional을 적절히 걸었다.
- [ ] 최소한 핵심 플로우에 대한 통합 테스트를 작성했다.
- [ ] 예외 상황(재고 부족, 로그인 실패 등)에 대한 처리와 응답이 일관적이다.
